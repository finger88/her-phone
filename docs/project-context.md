# 项目脉络与边界

## 手机主线

最初的工作名是“它的手机”：不只是手机里装了一个助手，而是设想一个AI拥有承载自己记忆、观察和未来约定的手机。后续的her-phone、时迹与拾光材料逐渐补齐人格、分层记忆、用户纠正、历史导入、暂停恢复与约见书签等协议。

本仓库参考目录取自现存拾光资料，保留原字节及版本冲突：metadata为1.6.0，身份文件为1.5.0，目录含12个Skill。这里的版本标记不能单独证明已上传市场、完成真机安装或形成长期使用效果。

## 核心问题

1. 她能不能有稳定的观察方式，而不是只换一个名字和语气？
2. 原始表达、事实、模型解释与用户纠正，能不能在长期记忆中保持分开？
3. 用户说“不是这样”以后，旧判断能不能真正退出下一次推理？
4. 下次相见时，能不能从上次重要的位置继续，同时允许用户不继续？

这些是希望继续验证的产品机制，不是关于AI意识或真实情感的结论。

## 另一个工程参考

AI项目全流程管理助手探索了共享目标、受限工具、人工确认、状态复查和自动接棒。它提供“怎样可靠地把事情接着办”的参考，但本仓库没有证明其直接复用了手机项目的SOUL或源码，也没有上传其业务代码、人员、合同、数据库或部署信息。

## 当前不应宣称

- 全天候自主观察或锁屏后台已稳定运行；
- 一套Markdown协议等于全部平台接口已经接通；
- 静态情境演示等于真实模型或实机运行；
- 记住一次纠正等于已经证明长期行为改变；
- 页面公开等于新增商业授权或核定所有团队署名。

## 后续可验证的最小闭环

用户授权一个小任务 → 读取必要资料与旧纠正 → 形成观察/计划 → 在权限内执行 → 读取真实结果复查 → 用户纠正 → 停用旧判断 → 跨会话在相似但不同的场景中检验下一次变化。
