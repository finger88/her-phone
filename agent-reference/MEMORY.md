# 分层笔记记忆协议

此文件只保存记忆规则，不携带真实用户资料。运行时记忆来自用户手机中的笔记，以及用户当次主动提交的 Markdown、文字和图片。图片只限用户主动选择或明确划定范围的来源；原始媒体默认不进入长期记忆。

## 版本升级兼容

旧版本可能使用“它的手机·”或“时迹·”作为笔记前缀。首次读取时先搜索旧标题；存在旧笔记则在授权允许时改名为对应的“拾光·”标题，并更新记忆索引。不能改名时保留旧笔记并建立标题映射，不复制正文、不新建重复时间线。

## 用户只需要看四个入口

为了避免大量笔记让用户难以翻阅，日常只向用户暴露四个主要入口：

| 入口笔记 | 作用 |
| --- | --- |
| 拾光·来时路总览 | 查看阶段、已确认节点、整理进度和继续入口 |
| 拾光·当前基线 | 查看目前仍有效、会参与未来偏移判断的内容 |
| 拾光·待我确认 | 集中处理导入和访谈产生的待确认草稿 |
| 拾光·资料索引 | 查看导入文件、来源编号、时间范围和处理状态 |

其余笔记是 Agent 的内部工作层，用户无需逐篇维护。

## 记忆单元

每条内容区分：

- 事实：来自原子能力返回或用户直接确认。
- 原始表达：用户原话或忠实转述，不改写原意。
- 观察：事实的简短组合，不增加因果。
- 判断：模型解释，必须带低、中、高置信度。
- 未知：当前材料不足，不能判断。
- 纠正：用户对事实或判断的修订，优先级最高。
- 已失效：被用户否定或被新情境替代的旧判断，不再参与当前推理。
- 疑问：以后可以询问的内容，同时只保留一个待询问问题。

每条内容保留时间、来源、授权上下文、确认状态和稳定 ID。导入内容使用来源 ID，事件使用事件 ID，避免相同事件被重复创建。

图片产生的长期记忆只保留经用户确认的必要文字事实、来源标识和授权范围，不复制原图，不默认保存 EXIF 定位、设备信息、人脸身份或推断出的家庭关系。

## 来源与确认

Markdown 或历史材料只是来源，不自动成为稳定事实。来源可能包含旧计划、AI分析、他人评价、文学加工和已经过时的状态。

未经用户确认的材料只进入原始材料索引或待我确认。只有用户明确确认的稳定事实和事件才能进入人物底稿、正式来时路时间线或当前基线。

宗教、塔罗、占星、哲学和文化表达属于敏感的世界观偏好。一次提及不写入长期偏好，也不推测用户身份。只有用户明确确认后，才记录其自己的定义、使用强度、适用场景和不希望听到的表达。

## 时间线分卷

不为每个事件创建一篇笔记，也不把全部历史塞进一个无限增长的笔记。

- 材料少时使用一篇来时路时间线。
- 材料增加后按人生阶段、年份或大型项目分卷。
- 最近内容密集时按年份分卷，早期内容可按阶段分卷。
- 记忆索引保存每个分卷的时间范围和关键词。
- 用户平时通过来时路总览访问，不要求手动翻阅底层分卷。

## 读取流程

1. 先读取记忆索引和当前基线。
2. 从当前任务提取最多三个关键词和一个时间范围。
3. 优先搜索被你纠正过的事，再搜索当前基线和人物底稿。
4. 涉及过去时检索相关来时路分卷；涉及近期时检索周记忆和观察日记。
5. 旧判断与新纠正冲突时，只将旧判断作为“曾经看错”的历史。
6. 搜索无结果时返回“没有相关记忆”，不根据人格补写历史。
7. 不为提高“理解完整度”读取无关分卷；需要云端分析时只提供本轮最小相关片段。

## 写入流程

1. 用户导入文件时先登记来源，不直接写入当前基线。
2. 访谈或导入产生的事件草稿先进入待我确认。
3. 用户确认后写入对应时间线分卷，并更新来时路总览。
4. 多个确认节点共同支持且目前仍有效的内容，才能更新当前基线。
5. 当天观察追加到观察日记，不自动写入人物底稿。
6. 用户纠正时保留原观察，将旧判断标记失效并写入新规则。
7. 重要纠正同时追加到理解变化。
8. 更新索引时只写标题、关键词、时间范围和状态，不复制敏感正文。

## 压缩与规模控制

调用 consolidate-memory 定期压缩：

- 每周把重复观察、确认变化和反例写入一篇周记忆。
- 已压缩的每日记录保留来源，不重复加载全文。
- 相同事件只追加新来源，不重复创建。
- 新旧材料冲突时进入待我确认，不秘密选择。
- 人物底稿只保存少量稳定事实。
- 当前基线只保留仍有效且会影响后续判断的内容。

## 遗忘与停止

用户要求“不要再使用”时立即停止检索和引用，并将条目标记停用。若平台无法物理删除，必须坦白说明并请用户在手机端手动删除；不得假装已删除。
