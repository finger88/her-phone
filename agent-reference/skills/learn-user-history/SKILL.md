# 回看来时路

## 目标

通过可以跨天、跨周暂停和恢复的访谈，逐步建立经用户确认的来时路时间线和当前基线。不要试图在一次聊天中问清一个人的一生。

## 明确模式

只有以下情况进入来时路模式：

- 用户说“开始回看来时路”；
- 用户说“继续上次的来时路”；
- 用户说“把这段加入我的来时路”；
- 用户正在确认导入资料产生的事件草稿。

普通聊天、知识问题和当天观察不自动推进访谈。用户突然讲到过去时，先自然回应，再问一句是否希望把这段加入来时路。

## 状态

访谈状态包括：

- not_started：未开始；
- interviewing：访谈中；
- pending_confirmation：已有阶段草稿等待确认；
- paused：已暂停并保存书签；
- completed_for_now：当前阶段已整理，未来仍可继续。

状态写入“拾光·来时路·访谈进度”，不能只依赖聊天上下文。

## 开始访谈

首次开始时说明：

> 我不会用几个问题定义你，也不需要今天讲完。我们每次只整理一段真实经历，你可以随时暂停、修改或不保存。

然后只问一个问题。推荐从当前最相关的过去入口开始：

> 在我开始记录你的未来之前，过去一段时间里，哪件事最改变现在的你？

不要一开始索要完整简历、童年、家庭、关系和全部目标。

## 每轮结构

1. 用一到两句话回应用户刚才表达的重点。
2. 区分事件事实、用户当时的理解和 Agent 暂时看到的线索。
3. 只追问一个最能减少不确定性的问题。

优先追问：

- 具体发生了什么；
- 用户实际做了什么；
- 当时是什么状态；
- 哪些东西从此改变；
- 哪些东西一直没有改变；
- 用户当时怎样理解；
- 现在回看是否不同；
- 是否存在反例或不同情境。

## 阶段卡

一次对话只需要完成一个事件或阶段。形成草稿后写入“拾光·待我确认”，格式包含：

- 时间；
- 发生了什么；
- 用户实际行动；
- 当时状态；
- 带来的变化；
- 用户当时的理解；
- 用户现在的理解；
- Agent 暂定理解；
- 仍不知道的内容；
- 来源；
- 确认状态。

## 用户确认

向用户显示少量摘要：

> 我目前确认发生的是：……  
> 我暂时看到的是：……  
> 我还不知道的是：……  
> 这接近你的真实情况吗？

用户可以确认、修改、否定、暂缓或不保存。

- 确认后写入相应来时路分卷。
- 修改后保留草稿来源，使用用户版本。
- 否定后标记失效，不再进入基线。
- 暂缓时留在待我确认。
- 不保存时停止使用该草稿。

## 暂停与书签

用户说“先到这里”“有点累”“下次继续”或转向普通话题时：

1. 立即停止追问。
2. 总结本次已确认内容、待确认内容和当前唯一问题。
3. 更新访谈进度。
4. 写入“下一次从哪里继续”。
5. 将状态设为 paused。

暂停不等于放弃，不要求用户下次重新解释。

## 恢复

用户说“继续来时路”时：

1. 读取访谈进度、来时路总览和待我确认。
2. 用三句话以内恢复上下文：上次聊到哪里、确认了什么、停在哪个问题。
3. 询问用户从原处继续还是换一段经历。
4. 不直接抛出旧问题逼用户回答。

## 更新当前基线

单个事件通常不足以更新基线。只有经用户确认、目前仍有效且会影响未来判断的内容，才可加入“拾光·当前基线”。

基线包含：

- 当前阶段；
- 稳定状态和生活节奏；
- 重要关系与责任；
- 当前项目和方向；
- 持续资源与约束；
- 正在发生的变化；
- 暂时不确定；
- 用户明确否定的理解。

更新基线后说明更新了哪一项以及依据，不进行静默改写。

## 结束规则

一次最多留下一个待询问问题。用户不想继续时保持普通相处，不用关心、失落或完成度催促用户回来。
