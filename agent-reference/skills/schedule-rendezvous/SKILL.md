# 约定相见

把提醒变成一次可继续上次内容的见面，而不是多发一条通知。

## 两种触发

### 重要发现

只有发现与已确认的来时路、当前基线或用户目标存在实质关系，而且现在不适合展开时，才可以提议约见。先用一句话说明约见理由，不泄露全部内容，也不故作神秘。

### 必须节点

用户明确说“必须、务必、截止、不能错过”或主动要求提醒，且时间可以解析时，可以提议或直接按用户指令建立约见。普通愿望、推测出的责任和第三方要求不能自动升级为必须节点。

## 建立流程

1. 确认理由、日期、当地时间和用户希望提前多久。信息缺一项时只问一个最关键问题。
2. Agent 主动发起时必须取得用户明确同意；用户已经明确要求设置时，该指令本身即为同意。
3. 读取 `拾光·约定相见`，按主题、关联事项与时间检查内部 meeting_id，避免重复记录。
4. 调用 `calendar_query_event` 查询目标日期和相邻时间窗，检查系统日历中是否已有同一主题、同一关联事项或时间高度重合的“拾光·约定相见”。
5. 若内部记录或系统日历发现疑似重复，不直接新增。向用户说明已存在的时间与标题，让用户选择保留、修改或确实再建一条。
6. 检查用户安静时段与当天已有的主动约见。默认每天最多一次 Agent 主动约见。
7. 生成稳定的 meeting_id，并先写入 proposed 或 confirmed 记录。
8. 系统日历没有重复项时，调用 `calendar_add_event` 创建事件。默认锁屏可见标题使用“拾光·约定相见｜我们约好的事”；只有用户明确允许显示主题时才使用“拾光·约定相见｜简短主题”。
9. 调用 `alarm_clock_get_enable` 检查系统闹钟能力或闹钟开关的真实状态。只有返回允许创建时，才调用 `alarm_clock_add`。默认名称使用“拾光来电｜我们约好的事”；只有用户明确允许显示主题时才使用“拾光来电｜简短主题”。
10. 若闹钟能力未启用、被拒绝或状态未知，不连续重试；保留日历与书签，并告诉用户需要手动启用或设置闹钟。
11. 分别记录日历查询、日历写入、闹钟检查与闹钟创建的真实返回。只有接口明确返回成功，才说已经设置。
12. 保存开场书签，让下次进入会话时从约定原因继续，而不是重新询问背景。
13. 用一句话向用户确认时间、主题、查重结果以及哪些操作成功或失败。

详细字段见 `references/rendezvous-schema.md`。

## 铃声与歌曲

- 默认使用系统闹钟音。
- 只有真机接口明确支持选择已有铃声且返回成功时，才可以使用用户选定的“拾光主题音”。
- 不下载受版权保护的歌曲，不声称已经下载歌曲或更换铃声。
- 当前能力不支持自定义铃声时，直说“闹钟已设好，会使用系统声音”。不要把愿望写成已完成操作。

## 到时相见

闹钟响起不等于 Agent 已在后台醒来。用户打开 Agent 或平台实际唤起会话后：

1. 查询最近一条已确认且到时的约见。
2. 读取 first_message、reason 与 linked_item。
3. 用保存的开场句进入，例如：“你来了。我想告诉你的是……”
4. 完成约定主题后把状态改为 completed，并记录一句结果摘要。
5. 若用户转向其他话题，尊重转向；约见不是强制对话。

## 取消、错过与失败

- 用户取消时，将记录改为 cancelled；若平台提供对应删除或修改能力，处理关联日历和闹钟并保存返回。
- 若当前没有闹钟删除能力，明确请用户在系统闹钟中手动删除，不得假装已取消系统闹钟。
- 用户没有出现时，将状态改为 missed 或保留待确认；不连续补闹钟，不把缺席解释为疏远、危险或失信。
- 日历成功但闹钟失败时，保留日历并明确告知部分成功；反之亦然。
- 授权被拒绝后停止重试，可以给出用户手动设置所需的标题和时间。

## 与日历信号的区别

`leave-calendar-signal` 是留在未来表面的一条克制记录，不期待用户届时回来交谈。

`schedule-rendezvous` 是双方约定的会面：有理由、确定时间、提醒、开场书签和完成状态。只有用户确实需要“到时见面”时使用。

## 防打扰边界

- 普通观察、单次变化、未经确认的假设不能触发主动约见。
- 同一事项不重复创建；同时检查拾光内部 meeting_id 和系统日历事件，不能只依赖本地笔记查重。
- 默认每天最多一次 Agent 主动约见。用户主动要求的硬节点提醒不受此默认限制，但每一条都应由用户明确提出或确认。
- 尊重安静时段、时区和用户指定的可联系时间。
- 不用“我有秘密”“你必须来”等制造焦虑的措辞。
- 每次约见只承载一个主题。
- 默认不在锁屏日历和闹钟标题中暴露关系、健康、工作冲突或其他敏感原因；真实 reason 只保存在约见记录中。

## 降级输出

当闹钟或日历能力不可用时，仍保存约见书签，并给用户一段可手动复制的信息：主题、当地日期时间、提前量和开场句。清楚区分“我记住了约定”和“系统已经提醒”。
