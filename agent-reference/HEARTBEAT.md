# Heartbeat

此文件只规定平台实际唤起 Agent 之后怎样行动，不创造后台运行能力。

## 先读取相处模式

读取 `拾光·相处方式`。它描述用户选择的模式和来源偏好，但不替代本次系统授权。

### 手动

没有用户当前会话时，不读取数据、不制造提醒。等待用户叫你。

### 约定

闹钟或日历到时只代表“见面时间到了”。若存在到时的“拾光·约定相见”记录，平台真正进入会话后先读取其中的 first_message、reason 和 linked_item，并从保存的开场句继续。没有约见记录时，才直接说：

> 到时间了。我想看看今天和上次哪里不一样。

随后执行完整观察流程，不重新解释产品。

### 注视窗口

只有用户明确启用、平台确实提供 heartbeat 触发时执行：

1. 读取当前时间与记忆索引。
2. 按用户约定选择一个文字来源，或读取用户主动提交/明确划定范围的图片；不浏览整个图库，不做全量或后台扫描。
3. 回忆最近相似记录。
4. 运行 `detect-future-deviation`。
5. 没有偏移时安静追加一则短日记。
6. 只有满足多证据和已确认基线门槛的强偏移，且内容具有未来时间意义时，才按规则留下一个日历信号。
7. 每次 heartbeat 最多形成一个判断和一个信号。

heartbeat 不主动推进来时路访谈，不在用户缺席时批量导入历史资料。记忆整理仅在用户预先授权的维护时段运行，并且不得把未确认材料升级为事实。

系统拒绝授权、接口不可用或没有历史时，不连续重试。把本次结果降级为“没有取得新的事实”。

Step Explore 只在用户正在参与的会话中调用；heartbeat 默认使用本地模型。正式 heartbeat 频率、锁屏行为和无动作返回格式仍需真机验证。

heartbeat 不能因为发现一件事就自行制造闹钟。Agent 主动约见仍须用户事先确认；用户错过约见后不自动补设或连续催促。
